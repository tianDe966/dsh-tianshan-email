# dsh-tianshan-email

> 给 DeepSeek Harness 一个**能发邮件的出口**：你不在电脑前时，它把进度和成果送进你的邮箱。

自建 SMTP，写自己的账号 —— 不经第三方邮件服务，也没有中间服务器。

- **一个工具 `send_mail`**：主题 + 正文，可选 HTML、可临时换收件人
- **一张设置页「tianshan邮件」**：服务器 / 端口 / SSL / 发件人 / 授权码 / 默认收件人 +「发送测试邮件」
- **授权码按 secret 处理**：浏览器侧脱敏，插件不写日志、不放进任何返回值
- **零平台绑定**：纯 Node + `nodemailer`，Windows / macOS / Linux 一样跑

---

## ✨ 它到底能干什么

装完之后，AI 多了一条**不打断你、但一定留痕**的汇报通道：

- **阶段性汇报**：长任务跑完、里程碑达成、一轮远程对话收尾时，按固定四段式发一封——当前项目、结果摘要、耗时与成本、下一步建议。你在手机上瞄一眼就知道要不要回来。
- **成果直接投递**：报告、日志、截图可以当附件发到邮箱，不用回电脑翻目录。
- **异步、可留档**：邮件不会被「正在输入中」打断，也不会像微信那样被刷过去；翻翻历史就知道 AI 昨天到底干了什么。
- **远程模式的默认出口**：合盖出门、改用手机时，配合 `dsh-remote-notify` 的远程标记，声音自动静音、汇报走邮件。
- **配置不藏在代码里**：SMTP 全在设置页点，改完立即生效，不用改文件、不用重启。

有两个边界要说清楚：

- **它不是通知触发器**——「对话完成 / 等待审批 / 等待提问 / 任务看板」这类事件驱动的自动邮件是 [`dsh-email-notify`](https://www.npmjs.com/package/dsh-email-notify) 的领域（Apache-2.0，可并存）。
- **它不替你收信**，也不做邮件客户端；只负责「往外发」。

## 🧩 和这几个插件搭起来才完整

单装本插件已经能用——你让它发什么它就发什么。但它真正的价值在于补上「人不在」的那一环。DSH 的三条触达方式正好互补：

| 你在哪 | 谁来找你 | 靠哪个插件 |
| --- | --- | --- |
| 电脑前 | 出声喊你一句，右下角同时浮出气泡 | [`dsh-voice-speak`](https://www.npmjs.com/package/dsh-voice-speak) |
| 手机上 | 微信消息、审批卡 / 提问卡，回个数字就继续 | [`dsh-channel-wechat`](https://www.npmjs.com/package/dsh-channel-wechat) |
| 不在线、或者想留档 | 邮箱收到四段式汇报，成果当附件 | **本插件** |

- **本插件 + `dsh-voice-speak`**：人在电脑前用声音最快；但声音你人不在就听不见 —— 所以再配下面的。
- **本插件 + `dsh-channel-wechat`**：微信负责「现在就要你拍板」（审批、提问），本插件负责「跑完了，你有空再看」（阶段汇报、成果归档）。**前者抢注意力，后者不抢。**
- **三个一起**：在电脑前 → 出声；人在路上 → 微信叫回、回数字继续；跑完的完整汇报 → 邮箱留档。

一句话：**该吵的时候吵（声音 / 微信），不该吵的时候留痕（邮件）。**

> 想让「人不在」自动切换，再配 `dsh-remote-notify`：进入远程模式后语音静默，邮件照发。

## 装什么

- **设置页「tianshan邮件」**：SMTP 服务器 / 端口 / 直连 SSL / 发件邮箱 / **邮箱授权码（secret）** / 发件人地址 / 默认收件人，外加一个「发送测试邮件」按钮，点一下就知道配置通不通。
  这张卡片属于插件自己（`src/client/`，esbuild 打成 `lib/client.js`），因为 DSH 目前不会给第三方 namespace 自动生成设置页。
- **工具 `send_mail`**：`subject` + `text` 必填，`to` 可覆盖默认收件人，`html` 可选。
  配置不全时返回 `status=failed` 并说明缺哪几项，不抛异常；授权码不会出现在任何返回值里。

## 安装

```sh
npm install dsh-tianshan-email
# 或本地目录
dsh plugin --profile web add link:D:/path/to/dsh-tianshan-email
```

装完重启 DSH，设置侧边栏会出现「tianshan邮件」页。

## 配置

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 例如 `smtp.qq.com`、`smtp.163.com` |
| 端口 | 465 配 SSL；587 一般配 STARTTLS |
| 直连 SSL/TLS | 465 选开，587 选关 |
| 发件邮箱 | 账号本身，例如 `xxx@qq.com` |
| 邮箱授权码 | **不是登录密码**，是邮箱设置里生成的 SMTP 授权码；留空则不发信 |
| 发件人地址 | 一般与发件邮箱相同 |
| 默认收件人 | 多个用逗号、分号或换行分隔 |

安全边界：授权码声明为 secret 字段，DSH 的设置服务在把值发往浏览器前就会脱敏；插件自身也不会把它写进日志、错误信息或工具返回值（`sanitize()` 会把它从任何将要外露的文本里抹掉）。

## 用法

配置完成后直接让 AI 发：

> 用 send_mail 给我的邮箱发一封测试邮件，主题「测试」，正文「hello」。

远程模式下更常见的一句话是：

> 这轮干完了，按四段式发封汇报到我邮箱。

## 不做的事

- 不做通知触发器（对话完成、审批、提问、任务看板）——那是 `dsh-email-notify` 的领域，两者可以并存。
- 不做自定义邮件模板系统：正文由模型按需要写，插件只负责发。
- 不缓存授权码到磁盘以外的任何地方。
